# Private owned native family trial

The explicit `preparation.native_family` value `owned-native-family-v1` selects
existing native family operations for the private RN paged-history owner with
TP8/ETP4, HC4/D2560 and bound NONE/MTP coordinates. The manifest must retain
`trial: true`, `graph_family: uncaptured` and the existing RN family/head choice.
The selection is omitted by default. The private campaign `inputs` command accepts
`--native-family owned-native-family-v1` and writes the choice into its immutable
profile manifest; `model` consumes that profile through `settings.profile_manifest`.
Each qualification rank receipt records the requested/actual policy and exact
binding for decode, MTP and prefill. These receipts explicitly distinguish prepared
capability from observed native invocation. Administrator profile transitions, reference
arithmetic graphs and reference-tile preparation are outside this trial region.

The capability is owned by Weights and adopted by target, MTP and prefill Buffers.
It does not change process-global family, attention, router, packed-expert or
padded-linear selectors. Buffers without this capability retain their previous
provider. RN attention preparation/cache ownership, ETP4 experts, linears, method,
context and capacity remain independently selected. The historical `ple_embed_bf16`
API consumes FP16 rows in this SM70 region; it does not enable native BF16 math.

HC writeback, normalization, activation/reduction and mix; RMS; attention-output
gating; unquantized PLE embedding, PLE gate/convolution; MTP stream addition; MoE
partial reduction; and convolution/history shifts use the existing checked
native ABI. PLE retains its live-row device operand and independent-row mode.
Shifts retain the existing <=16-tap native capability; larger windows keep the
original Torch operation. Packed PLE table decoding is unchanged.

Native entrypoints are warmed on initialized temporary operands inside the
existing OwnerPreparation physical-memory accounting window. Positive device
completion retires warmup storage before State admission; no new serving tensor
workspace is retained. All ranks agree the manifest and actual native module/
source records. Raw writes publish output mutation metadata. The module is
retained with its borrowers through ordinary engine/graph retirement, with no
new mutable process policy or request-time compilation.

This is a different, unqualified numerical profile: FP16 operands/stores and
existing FP32 reductions with `--fmad=false` do not prove Torch bit identity.
No tolerance or output-quality requirement changes. Current source checks do
not qualify SM70 execution. Required gates remain the existing native family
operator controls, actual serial/MTP and partial-commit/graph controls, all-eight
full-session capacity and NUMA checks, full-model output comparisons and the
unchanged teacher/distribution measurements where outputs differ. Compare the
same source/configuration without instrumentation for throughput before adoption.

The motivation is a verified dispatch gap, not a measured causal speedup: the
campaign's `reference` profile retains Torch family operations even when an owned
Q8/attention/expert module is resident. This trial does not fix the independent
multirow/MTP Q8 reference preparation route or generalize prepared M32 linears to
120-row Buffers. Those require their own contracts and evidence.
